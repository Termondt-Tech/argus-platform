## Name

**`Gomeisa`** — β Canis Minoris, from Arabic *al-ghumaisa'*, **"the bleary-eyed
one"** (also glossed "the watery-eyed one" / "the weeping one"; IAU-approved
2016). Found outside the pool — Rastaban is the only reserved candidate left and
its dual-watchdog/consensus reading doesn't match this release, the pattern since
v0.3.6.

The fit is item 6, the release's one real finding: `scripts/argus-snapshot.sh`
resolved the audit database by a hardcoded path, and after the cutover would have
kept backing up the frozen **cert** database forever while every downstream
signal agreed it was fine — the copy succeeded, `verify_chain` passed,
`argus-pull-check.sh` reported `ok`. Nothing was blind. The eye was open, running,
reporting, agreeing with itself — it just wasn't resolving the right subject.
**Bleary, not shut**, which is a sharper description of this defect than "blind"
would be, and a different failure shape than the two double stars already spent
here (Albireo, Mizar — one point resolving into two) or Alpheratz (one name, two
readings): this is one name, correctly pointed for months, quietly drifting onto
the wrong subject the moment the ground under it changed (`db_path` diverging in
v0.3.17). It stretches, loosely, to the release's other four items too — several
checks here had been running on a slightly out-of-focus premise (a provisional
`[coa]` note, an unverified calendar) and this release is the one that actually
looked closely enough to bring them into focus, rather than just re-running the
same check.

Qualifies as an "eye" name by the adjectival route, the same standing already
given to Alterf ("the glance") — not a noun for the eye itself, but a description
of one. Confirmed against
[star-facts.com](https://www.star-facts.com/gomeisa/),
[University of Illinois's Star of the Week](http://stars.astro.illinois.edu/sow/gomeisa.html)
and [Wikipedia](https://en.wikipedia.org/wiki/Beta_Canis_Minoris) before being
spent — **Almach** (γ Andromedae) was considered and rejected first: its
etymology is "caracal/desert lynx" and "foot of the chained woman," no eye
reading in any source checked, and using it would have been the "picked only
because it sounds good" mistake the convention warns against.

**Rastaban stays reserved.** The pool remains otherwise empty — every release
after this one takes a found name until it's refilled.

### 1. Final go-live risk caps — sandbox synced to live's min-size numbers (C1, done)

→ [`docs/go-live-findings.md` C1](../go-live-findings.md)

Cert (`argus.sandbox.toml`) had been running cert-era risk numbers scaled to a
~$100k account; live (`argus.live.toml`) had already moved to live-min-size
numbers on an earlier pass. **Resolved by syncing cert to live rather than by
re-declaring the divergence** — cert should exercise the same numbers live will
actually run:

| Key | sandbox — was | sandbox — now | live — now | dev — now |
|---|---|---|---|---|
| `risk.max_concurrent_positions` | `2` | **`1`** | `1` | `1` (unchanged) |
| `risk.max_loss_per_position` | `1250.0` | **`950.0`** | `950.0` | **`950.0`** (was `1250.0`) |
| `risk.daily_max_loss` | `2500.0` | **`950.00`** | `950.00` (was `1900.00`) | `1740.0` (unchanged) |
| `risk.max_contracts_per_position` | `2` | `2` (unchanged) | `2` | `2` |

**The welded invariant re-derives at `1 × 950 = 950`** in both sandbox and live
(dev is untouched by the equality — its own `daily_max_loss` stays independently
sized). `tests/test_config_profiles.py`'s `ALLOWED_DIVERGENCE` had five entries
whose documented differences no longer exist after this sync — **retired rather
than left stale**: `(sandbox, live, risk.max_loss_per_position)`,
`(sandbox, live, risk.daily_max_loss)`, `(dev, live, risk.max_loss_per_position)`,
`(dev, sandbox, risk.max_concurrent_positions)`,
`(dev, live, risk.max_concurrent_positions)`. **Sandbox↔live divergence drops
from ten declared keys to eight** — `risk.position_size_pct` is now the one risk
rail still genuinely account-sized rather than min-size-sized.

**Consequence, now applied**: `docs/go-live-findings.md`'s own C9 row read
"sandbox↔live divergence is now 10 — exactly the cap," which went stale the moment

### 6. The nightly snapshot was backing up the cert database by literal path — FIXED and DEPLOYED

→ `scripts/argus-snapshot.sh`, `tests/test_deploy_wiring.py`

Found while drafting item 5, not looked for separately. `scripts/argus-snapshot.sh`
opened the audit database at a hardcoded `file:/data/argus.db?mode=ro`. Harmless
while one database existed; **a live-cutover blocker the moment `argus.live.toml`
got its own `db_path = "argus-live.db"`** (v0.3.17, deliberately a different file
so live can never continue the cert hash chain). Post-cutover the nightly backup
would have copied the frozen **cert** database forever, and every downstream
surface would have agreed it was fine: the copy succeeds, `verify_chain` passes on
an intact-but-finished chain, a fresh `argus-<stamp>.db` lands nightly, and
`argus-pull-check.sh` reports `ok`. **The live audit log — the only durable record
of real orders and real fills — would have had no off-volume copy, and nothing
would have said so.**

- **Created by v0.3.17's own `db_path` fix** — closing one cutover blocker opened
  another, one script over. Same class as v0.3.21's unprivileged-run misreport and
  the earlier `docker compose run` vs `docker exec` finding: **a check performed
  against the wrong subject proves nothing about the right one.**
- **Fixed by resolving the source through `Config.load()` with no argument** — the
  same call `python -m argus` makes, so the backup finds its source the way the
  process finds its destination. The source path is printed on every run; a
  missing source refuses loudly rather than skipping or falling back (the missing
  case is the cutover window itself: profile flipped, process not yet restarted
  under it).
- **The rotation glob (`argus-*.db`, `$KEEP`) counts files across profiles** — a
  profile change means this directory transiently holds snapshots of two different
  databases under identical-looking names, and the new one's runs rotate the old
  one's out. Documented as the existing staging-window model working as designed
  (the NAS is the archive); the live-cutover procedure takes one final cert
  snapshot and moves it *out* of this glob before the flip, which is the only
  copy of that distinction that survives on the droplet.
- `tests/test_deploy_wiring.py::test_the_backup_never_names_a_database_by_literal_path`
  asserts the **absence** of any `.db` literal in the script (not merely the
  presence of the loader call) — a rewrite that reintroduces the bug in a new
  spelling still has to write a filename down somewhere, and this fails on it.
- **`scripts/` + `tests/` only. Inert for the restart classifier — not a `src/`
  change, so the trading process was unaffected by its own arrival** — but it
  rides the same checkout as this release, so it is deployed as of this tag.
  **Reading one nightly journal line for the new `source ...` output is the
  remaining action item under G2** — the fix landing is confirmed by the deploy,
  the fix *working* wants one overnight run's output read back.
