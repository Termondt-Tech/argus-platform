## Fixed

**The trading credential was not keyed on the same authority as the trading
endpoint, and going live was secretly a second, undocumented step.**
`TastytradeSession.is_test` has always derived the *endpoint* from
`config.environment` — the sandbox-first boundary. But every trading call site
built its credential from a bare `TastytradeCredentials.from_env()`, which
read one unprefixed pair (`TASTYTRADE_CLIENT_SECRET` /
`TASTYTRADE_REFRESH_TOKEN`) regardless of environment. So the documented
cutover — `/etc/argus/host.env`'s `ARGUS_ENV` flip, "the live cutover is this
one file changing" ([config profiles](../decisions/2026-09-04-config-profiles.md))
— was never the whole story: reaching the live API also required hand-swapping
those two *values* in `/opt/argus/.env`, a step no runbook named and no deploy
assertion could see.

That gap was three real costs, not one theoretical one. **Rollback was
asymmetric** — flipping `host.env` back to `sandbox` does not un-swap a value,
so a botched cutover's rollback path lands in the same failure as the forward
path. **It could not be rehearsed** — proving the live registration
authenticates requires overwriting the credentials cert operation depends on.
And **the failure mode, if the swap was forgotten, was expensive rather than
fast**: a live profile presenting a cert token to the production API fails
`invalid_grant`, and `_login_with_retry` spends six attempts ten minutes apart
— deliberately, to stay under tastytrade's undocumented IP-block threshold —
so a missed step on cutover morning cost the better part of an hour before the
process gave up.

**Not a safety defect.** `is_test` already derives from `environment` alone,
so no cert profile could ever have routed a live order regardless of which
values sat in the credential variables — the sandbox-first guarantee was
intact throughout. The defect was operational: an unreversible, unrehearsable,
undocumented second step sitting underneath a documented one-step procedure.

**Fixed by keying the credential on the same config authority as the
endpoint.** `broker.trading_credentials(config)` reads
`TASTYTRADE_TRADING_CERT_*` for every non-live environment and
`TASTYTRADE_TRADING_LIVE_*` under `environment = "live"` — mirroring
`market_data_credentials`'s existing `marketdata.source` branch, which was the
only place in the codebase this pattern had ever been applied. Both trading
worlds' credentials now live in `.env` at the same time; the profile flip
alone decides which one loads, so the cutover and its rollback are
symmetric and the live registration can be shape-verified (though not yet
login-verified — see Scope) before cutover day.

## Added

**Every credential slot names both axes it was missing one of.**
`TASTYTRADE_<ROLE>_<WORLD>_<FIELD>` — role first, so `grep TASTYTRADE_TRADING_`
is a complete audit of every credential that can reach an order:

| Slot | Required |
|---|---|
| `TASTYTRADE_TRADING_CERT_*` | Always — every non-live profile, and the market-data fallback |
| `TASTYTRADE_TRADING_LIVE_*` | Only under `environment = "live"` |
| `TASTYTRADE_MARKETDATA_LIVE_*` | Whenever `[marketdata] source = "live"` — true in both shipped profiles |

The old unprefixed names (`TASTYTRADE_CLIENT_SECRET`, `TASTYTRADE_REFRESH_TOKEN`,
`TASTYTRADE_LIVE_CLIENT_SECRET`, `TASTYTRADE_LIVE_REFRESH_TOKEN`) are **removed,
not aliased** — an AST test (`tests/test_credential_slots.py`) fails if any
comes back outside a comment. They were also byte-identical to TOMIC's own
variable names, isolated only by living in separate `.env` files; the rename
retires that shared-shell footgun as a side effect
(`docs/tomic-argus-concurrent-operation-assessment.md` Area F).

**Three structural guarantees, each mutation-checked:**

- **The live refusal is free.** `trading_credentials` under `environment =
  "live"` reads the live trading slot through the existing `from_env`, which
  already raises `MissingCredentialsError` naming exactly the missing
  variables — so a live profile with no live registration provisioned refuses
  to start, before any network call, with no separate check to write. It lives
  in `broker/session.py`, deliberately **not** `config.py`: a fail-closed
  config loader has no business reading the environment.
- **A live slot carrying cert values is refused at startup.** Not
  hypothetical — the migration itself manufactures the failure mode:
  moving to the new names is additive (copy existing values into the cert
  slots, add the live ones separately), and an operator who copies into the
  live slots too ends up with well-formed live variables holding cert values.
  `_refuse_cert_values_in_the_live_slot` compares values and reports only
  names.
- **A bare `from_env()` is now structurally banned in `src/`.** Before this
  release it *was* the trading path; after it, that exact line is the bug —
  cert credentials reached silently under a live profile, at whichever call
  site was missed or added later. An AST sweep enforces it can never come
  back.

**`/status` and the startup line now name the credential SLOT — the config
fingerprint's missing half, one layer further out.** `version` says which
code; the config fingerprint (v0.3.17) says which config bytes; neither ever
said which tastytrade *registration* a session authenticated with, and until
this release that was answerable only by reading a live process's memory.
`credential_slot_labels(config)` is a pure function of `environment` /
`marketdata.source` — pinned by an AST test to read no environment itself, since
it feeds a page served over the control surface — and is lifted onto
`StatusSnapshot` beside `config_profile`, not through the dataclass-converter
`_SEAMS` sweep the 2026-09-02 under-copy fix built (that sweep covers a
different failure shape and does not apply to a two-scalar constructor
argument). Names only, no colour state: nothing here is actionable-when-wrong,
because wrong cannot start.

**`tools.credcheck` walks the full (role, world) grid** rather than the old
flat four-variable list — per-slot required-when text, a half-set check (one
of a pair present without the other), the live/cert identical-value checks
extended to all four live-vs-cert comparisons (trading and market-data sides
both), and a note on whether the two live slots are one production
registration or two.

**`.env.example` restructured to the grid**, with the fallback and the
required-when conditions stated per slot, and its stale config-profile prose
(a pre-v0.3.18 `ARGUS_CONFIG` default, `ARGUS_ENV` described as overriding
`environment`) corrected in the same pass since it sits directly above the
credentials it was being rewritten alongside.

## Deploy

**`src/` + tests + `.env.example` + docs. No new config KEY** — every existing
key in both profile files is unchanged in shape or value. **But
`argus.sandbox.toml` and `argus.live.toml` both move**, comment-only (the
`[marketdata]` section's variable-name reference), so the config fingerprint
changes on both bind mounts alongside the image. This is a `build: YES,
config: YES, restart: YES` release under the v0.3.20 classifier.

**The deploy is not self-contained. `.env` must carry the new names on every
host BEFORE the image that reads them, and no image can do that step.** Runbook
§8.1 has the add → deploy → delete ordering — add the six new variables
alongside the four old ones (copying cert values into the cert slots, the
live registration's own values into the live trading slot), confirm shape with
`tools.credcheck`, then deploy, then delete the old four once the new image
has run a session. **On this release, that step was completed by hand ahead of
the code deploy** — the droplet's `/opt/argus/.env` and the operator's local
`.env` both carry the new names already.

```bash
cd /opt/argus && scripts/argus-deploy.sh --dry-run v0.3.22
```

Expect `build: YES` (naming `src`), `config: YES` (naming both
`argus.sandbox.toml` and `argus.live.toml`), `restart: YES`. Read the config
diff: it should be comment-only on both files, no key added, removed, or
changed in value.

```bash
cd /opt/argus && scripts/argus-deploy.sh v0.3.22
```

**After the restart, confirm on `/status` rather than in the file** — the
credential slot is now readable live:

```bash
curl -fsS -H "Authorization: Bearer $ARGUS_KILL_TOKEN" \
     http://<tailscale-ip>:8443/status | jq '{version, config, credentials}'
```

Expect `credentials.trading` to read `TASTYTRADE_TRADING_CERT_*` (this is a
`sandbox` deploy) and `credentials.market_data` to read
`TASTYTRADE_MARKETDATA_LIVE_*`.

### Rollback

`scripts/argus-deploy.sh v0.3.21` — image and both config files roll back
together. **Do not delete the new `.env` variable names as part of a rollback
sweep**: v0.3.21's code reads the old unprefixed names, which must therefore
still be present, but the new ones are harmless to leave in place unread. The
migration's ordering (add, deploy, delete) is exactly what makes this rollback
safe without a second `.env` edit.

## Scope

**One thread: the credential wiring gap this session's design pass
(`docs/decisions/2026-09-09-trading-credentials-are-environment-keyed.md`)
found and closed the same day**, signed off on option (b) — the full
(role, world) rename — over the cheaper two-variable addition, because going
live opens `.env` by hand regardless and the rename also retired the TOMIC
name collision.

**Two things the design got wrong, corrected during the build.** It claimed
`tools.account --config argus.live.toml` becomes a pre-cutover rehearsal of
the live registration; it does not — `tools/account.py`, `tools/loop_lag.py`,
and `tools/order_smoke.py` all refuse `environment = "live"` by their own
guard, predating this work, and none of those refusals was relaxed here. **So
nothing authenticates the live trading registration until the cutover
itself** — a new open question (decision record §7.7), not yet resolved: a
read-only login probe, or accept first-day-live as the first real exercise,
the same posture the daily max-loss breaker is already in. And the `/status`
addition needed no `_SEAMS` entry, contrary to the design's checklist —
corrected in the record.

**Not in this release, and reported here rather than acted on, per this
session's scope:** `tests/test_config_profiles.py::test_value_divergence_is_declared`
fails on `main` independent of this work — `argus.live.toml`'s live-min-size
risk numbers (commit `3595530`) were not added to `ALLOWED_DIVERGENCE`. The
welded invariant holds (2 × 950 = 1900), so this is a missing allowlist entry,
not a config defect; left alone because declaring intentional divergence is
Richard's call, not a byproduct of a credentials release.

**Test suite: 2062 passing** (the one failure above, pre-existing, not
introduced here), **up from 2046 — 17 net new.** 7 in the new
`tests/test_credential_slots.py` (the two AST structural guarantees, the
pre-rename names' absence, the label function's environment-blindness — one
parametrized four ways); the rest in `tests/test_session.py`, covering
`trading_credentials` across all three environments, the identical-pair
refusal, and the free live refusal. Each of the three structural guarantees
was mutation-checked directly against the change that would break it
(reverting a call site to a bare `from_env()`, un-keying `trading_credentials`
from `environment`, deleting the identical-pair refusal) — all three caught.
