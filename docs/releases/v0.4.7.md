*Argus had a nightly report that answers "what happened today?" and nothing that
answered "what has this made, net of fees, this week / month / year?", and nothing
had ever compared the broker's own record of the account to Argus's by anything but
a human reading two screens. This release closes both: a rebuilt-nightly ledger
(`argus_fills`, `trades`, `days`) joined to the broker's transaction history
(`broker_txns`, `recon`) per `order_id`, reconciled **to the cent, with no
tolerance**, pushed into a Google Sheet whose report tabs (`Dashboard`, `Weekly`,
`Monthly`) are pure formulas over that data. → [decision](../decisions/2026-09-22-ledger-and-sheets.md)*

*Named per the Argus's Eyes convention. The pool's only name, **Rastaban**, is
reserved for "a second, independent validation loop [that] cross-checks one rail's
verdict against another **before a high-risk action fires**" — and this release
gates nothing; it is read-only, runs after the trading day is already over, and an
AST test pins that `tools.ledger` cannot reach the submission path at all. Spending
Rastaban on a release with no gate would cheapen the one it is actually held for, so
the name comes from outside the table, the pattern since v0.3.6. **Kochab**, β Ursae
Minoris — from the Arabic *al-kawkab*, "the star," specifically *al-kawkab
ash-shamaliyy*, "the north star" — was **itself the pole star** for roughly 1500
years (circa 1500 BCE–500 CE), before precession carried the celestial pole on to
Polaris. Today Kochab and its neighbor Pherkad are called, since antiquity, **"the
Guardians of the Pole"**: they wheel around Polaris (γ UMi — spent on **v0.3.7**,
"the Unmoving Eye," the release about state that holds still regardless of what
churns around it) rather than mark it themselves. **The fit is that demotion,
verbatim.** Before this release Argus's own gross was the only number in the room —
`tools.desk` and `tools.mark` scored the day and nobody checked them against
anything. Now **"Broker gross, not Argus gross, is what the headline P&L sums…
Argus's gross sits beside it as the check"**: Argus's own count stops being the pole
and becomes a guardian circling the broker's, the way Kochab once *was* the
reference point and now keeps watch over the one that replaced it. Qualifies by
tradition rather than literal "eye" etymology, the standing already given to Alcor,
Arcturus and Polaris itself; it also claims a companion of an already-spent name
(Polaris), the Mizar/Alcor, Zubeneschamali/Zubenelgenubi, Grumium/Eltanin,
Kuma/Grumium, Gorgonea Tertia/Algol, Alshain/Tarazed pattern. **Confirmed against
two independent sources** (EarthSky, Sky & Telescope) before being spent — the
"Guardians of the Pole" epithet and Kochab's own former-pole-star history are both
well attested; no second-source flag is owed. **Rastaban stays reserved; the pool is
otherwise empty.***

## What changed

### 1. `tools.ledger` — the Argus side (read-only, `mode=ro`, no lock)

Not a new scorer. Per trading day it calls `desk.load` + `desk.summarize` — the same
objects the EOD digest already reads — and a trade's gross **is**
`ClosedPosition.pnl`. Fills come from `shadow.marker.read_fills`.

- **`Fill.broker_order_id`** (new, `int | None = None`, additive) carries the join
  key from `order.fill`'s `broker_order_id` payload field through to `marker.Fill`,
  so there is still exactly one decoder of that audit category.
- Three CSVs / data tabs: **`argus_fills`** (one row per `order.fill`, `buy_sell`
  from the cash sign — the broker relabels leg actions on a chained book),
  **`trades`** (one row per trade idea, `outcome` ∈ `closed` / `held_to_expiry` /
  `partly_closed` / `unpriceable`, `delta_source` and `version` so v0.4.6's
  mid-implied-delta split can never be pooled by accident), **`days`** (one row per
  ET trading date including no-trade days, starting at the first session whose close
  postdates the DB's first `process.start` — so the 2026-09-15 cutover day, which ran
  in cert, is not a phantom zero row).
- **Money is fixed two-place strings**, rounded to the cent in ONE function; the
  shared scorer stays float. The broker side and reconciliation compare in
  `Decimal`.
- **A held-to-expiry trade's `gross` is blank, never `0`**, until the broker's
  settlement record exists — a blank reads as unknown, a zero reads as a scratch.
- **The whole ledger is rebuilt every run — never appended, never upserted.**
  Idempotent by construction: a re-run, a catch-up, or two runs in one evening
  produce the same Sheet, and a `PROVISIONAL` day becomes `OK` the next night with
  no "update the old row" logic.

### 2. Google auth — a service account, not OAuth

→ [decision, "Google auth"](../decisions/2026-09-22-ledger-and-sheets.md#google-auth-a-service-account-and-the-oauth-dead-end)

OAuth was tried first and abandoned the same day: an External OAuth app cannot leave
"Testing" — where refresh tokens expire every 7 days — without a domain, a privacy
policy and brand verification, none of which a one-person ledger job should need.
Workload Identity Federation does not apply either — a droplet has no platform
identity to federate, so using it would mean running our own OIDC issuer.

- **`tools.rs256`** (new, stdlib, ~50 lines): PEM → DER → PKCS#1 v1.5 padding →
  one `pow()`. Signs and nothing else — no verification path exists to misuse.
  **Every signature is pinned byte-for-byte against `openssl dgst -sha256 -sign`**
  in `tests/test_rs256.py` (PKCS#1 v1.5 is deterministic, so the comparison is
  exact), and **verified against real Google 2026-09-22**: `sheets check` signed in
  as the service account and created data tabs in the real spreadsheet.
- **The scope is `spreadsheets`; the fence is the SHARE, not the scope.** A service
  account's token carries the scope but reaches only files shared with its
  `client_email`. No project role.
- **The key is never in `.env`**, the trading container's `env_file` — it would
  otherwise be visible in `docker inspect` and land in `/proc/<pid>/environ` for
  anyone with docker-group access. It lives at `/etc/argus/argus-sheets-key.json`
  alone, mode 400, owned by uid 10001 (the container's own non-root user — an
  earlier draft said `root:600`, which the container could not read), and is
  mounted read-only into the ledger's Sheets **push** step only — never into the
  ledger build, which reads the trading database and has no business holding an
  external credential. `.gitignore` already named the key patterns (google-oauth,
  service-account, client_secret) before this release; `a58ebb8` added two
  worktree-local entries alongside them.
- **`python -m argus.tools.sheets check`** (new, its own module, no `--config`,
  imports no `argus` runtime / `sqlite3` / `tastytrade`, AST-pinned): signs in,
  creates any missing data tab, and **proves Editor access even when nothing is
  missing** by setting a tab's title to what it already is — otherwise `check`
  would pass on a read-only share and the first real push would fail.

### 3. The broker side — `tools.broker_ledger`

→ [decision, "The broker side"](../decisions/2026-09-22-ledger-and-sheets.md#the-broker-side-as-built-2026-09-22)

One paginated, read-only `Account.get_history`. An AST test pins that the module
cannot reach the submission path and that the SDK import sits **inside**
`fetch_history`, so every pure function — and every ledger run without `--broker` —
needs no trading session at all.

- **Reached only through `tools.ledger --broker`** (off by default; a local run
  touches no network and needs no credentials).
- **The broker's numbers are THE numbers.** Argus's gross and its `order.submitted`
  fee estimate ride beside them as a check, matched per `order_id`, compared in
  `Decimal`, **to the cent with no tolerance** — a tolerance absorbs exactly the
  defect this exists to find.
- **`days` and `trades` gained broker columns at the end**
  (`broker_fees`/`broker_net`/`net`/`recon`; `fees`/`net`/`recon`) — no existing
  column moved, so the Sheet's own formulas were untouched by this addition.
- **Two new data tabs**: **`broker_txns`** (one row per `Transaction`) and
  **`recon`** (one row per trading date — `gross_diff`, `fee_diff`,
  `unmatched_argus`, `unmatched_broker`, `estimated_fee_rows`,
  `settlements_pending`, `status`).
- **Status per day, first match wins**: `BROKER_UNREAD` (tonight's fetch failed),
  `DIFF` (an order id on one side only, or a cent of gross/fee disagreement),
  `PROVISIONAL` (agrees so far but something is still estimated or pending),
  `OK` (every order matched, exact, nothing pending).
- **A broker row with no `order_id` is `unmatched_broker` and makes the day `DIFF`**
  — a cash settlement (so a failed flatten is loud) or anything foreign (the account
  is dedicated to Argus, non-negotiable).
- **A failed fetch blanks nothing**: every day reads `BROKER_UNREAD`, the Argus side
  writes as usual, the next rebuild picks the broker back up. `broker_txns.csv` and
  `recon.csv` are written only when the broker was actually asked, so an empty file
  never overwrites a real one with "the broker reported nothing."
- **Run against the live account, 2026-09-22: 4 days, all `OK`.** Gross
  0 / 90.00 / 100.00 / −730.00, fees 0 / −9.76 / −9.76 / −48.80, every `gross_diff`
  and `fee_diff` exactly `0.00`, 50 broker rows against 49 Argus fills (the broker
  slices fills differently at settlement; the join is per **order**, so that
  difference is expected and reconciles anyway).
- **One design assumption overturned by that live read**: `is_estimated_fee` is set
  on **every** row, including days whose fees already match the clearing firm's
  confirmation to the cent — so it does not mean "not yet finalized." It is now
  recorded and counted but decided on by nothing; `PROVISIONAL` now means what it
  says, a trade whose result is not yet known.

### 4. The Sheets push and the report tabs

- **`tools.sheets push`**: stdlib `urllib`, tested against a fake endpoint,
  **replaces exactly the data tabs** by whole-column reference (`days!A:A`), so every
  formula and chart on the report tabs survives a nightly refresh untouched. One
  real defect found on the first live push: the grid-grow request addressed a tab by
  **title**, which `updateSheetProperties` ignores (it takes `sheetId` only) — it had
  been silently resizing `Sheet1` and would fail outright the moment that tab was
  deleted. Fixed to resolve each tab's real id and refuse to resize one it can't
  find.
- **`tools.sheets report`**: builds `Dashboard`, `Weekly`, `Monthly` and a hidden
  `calc` tab, all formulas over the data tabs, run **by hand, never nightly** — so
  the views are current the moment a push lands and every number is traceable to the
  row it came from. **Four defects found by reading the live spreadsheet's computed
  cells back**, each a plausible wrong number rather than a visible error, each now
  tested: `SUMIFS` inside `ARRAYFORMULA` isn't array-aware and repeats row one down
  every week; `QUERY(..., 1)` over a range starting at row 2 ate the first trade as
  a header; two spilling `QUERY` blocks sharing rows render `#REF!` with no reason
  given; and number formats are per cell block, not per column, so a win rate can
  read as `$0.29`.
- **A period filter on the dashboard**: one strict dropdown (`All` / `YTD` / `This
  month` / `This week` / `Last 30 days` / `Custom`), resolved once into `calc`, read
  by every KPI, grouping and chart series — a test fails on any whole-column
  aggregate that skips it. **Anchored on the last session in the ledger, never the
  clock**, so a Saturday or a pre-push read cannot silently exclude the newest day.
- **Verified against the live spreadsheet, 2026-09-22**: net −$608.32 across 4
  sessions, tying to the three broker confirmations, no error cell on any tab, the
  filter exercised across `All` / `This week` / `Custom` re-deriving correctly each
  time.

### 5. The last step of `argus-eod.sh`

- **After delivery, on purpose.** The digest arriving is the job's whole point;
  nothing about a spreadsheet may stand between the report and Slack.
- **It can never fail the unit.** A non-zero exit from `argus-eod` means exactly one
  thing — the digest did not arrive — so every ledger/Sheets call sits inside `if
  !`; under `set -e` plus the ERR trap a bare failing command would page as a job
  failure and skip retention.
- **The Google key is mounted into the push alone**, via `docker compose run -v`
  inside the script — no `docker-compose.yml` change, which is why this release
  needs no new bind mount for the deploy classifier to learn.
- **A missing key or spreadsheet id is a SKIP, CSVs still written** — the
  missing-webhook rule applied to a missing credential.
- **A third `argus-pull.sh` arm** mirrors the ledger CSVs to the NAS, independent of
  the snapshot and transcript arms; six wiring tests pin the whole thing (last step,
  never fails the unit, key scoped to the push, `mode=ro` everywhere, no writer
  lock, no submission-path import).

## Why it's safe

- **Never writes to either database, never takes the writer lock.** `mode=ro`,
  always — pinned structurally, same standing as every other read-only tool in this
  codebase.
- **The broker call is `get_history` and nothing else.** An AST test pins that
  `tools.ledger` imports nothing from `execution/`'s submission path.
- **Runs after the trading day, in its own one-shot container, with its own failure
  line.** A ledger or Sheets failure cannot reach trading or cost the EOD report —
  the report is already delivered by the time this step starts.
- **`tools.rs256` signs and nothing else** — no verification path, so there is
  nothing there to be tricked into trusting.
- **Nothing reads another program's prose.** The ledger reads the audit chain and
  the broker API, never the EOD transcript.
- **No schema change, no migration.** `Fill.broker_order_id` is an additive
  dataclass field decoded from an existing payload key; nothing upstream of
  `marker.py` changed.
- **The report tabs can't be clobbered by the nightly push** — `push` sends no
  formatting request and touches only the named data tabs; a tab the module doesn't
  name is never touched, so an operator's own work on another tab is safe by
  construction.

## Deploying it

**Timing:** anytime — this is a read-only reporting path with no trading-side
effect, so there is no "nothing held" constraint the way an exit-path or gate
release has. The nightly `argus-eod.timer` (16:45 ET, enabled since v0.4.4) picks
the new step up automatically on the next scheduled run after the image restarts.

**Deployed 2026-09-22, after the close.** Steps below are kept as the record of
the procedure that was actually run.

### 0. On the workstation — confirm

```bash
./.venv/bin/python -m pytest -q
```

Expect **2,716 passed, 1 skipped**. Confirmed.

### 1. Tag

```bash
git push origin main && git tag -a v0.4.7 -m "v0.4.7 — Kochab" && git push origin v0.4.7
```

Done.

```bash
/opt/argus/scripts/argus-deploy.sh --dry-run v0.4.7
```

Not under `sudo`. Expect `config: no` / `build: YES` / `restart: YES`, and **no**

job, not a new unit, and the checkout updates it in place. Then:

```bash
/opt/argus/scripts/argus-deploy.sh v0.4.7
```

Done; read-backs confirmed (`version: v0.4.7`, `config.sha b941e29cc1bf` unchanged).

### 4. On the NAS — nothing new

The ledger CSV arm in `scripts/argus-pull.sh` shipped and was copied to the NAS the

this release.

no timing constraint. The ledger step simply stops running on the next nightly job;

## What this release does NOT do

- Does not gate any trading decision — no `PreTradeGate` input, no strategy input,
  no size effect, no rail, no alert threshold on the ledger's own numbers.
- Does not touch the exit path, the watchdog, reconciliation, or the kill switch.
- Does not parse settlement records ahead of a held-to-expiry outcome (Richard,
  2026-09-22): a spread reaching expiry is itself a failure of the 15:30 flatten, so
  Step 2 leaves it to surface as `DIFF` with the broker's own description, and a
  real example becomes a fixture if it ever happens.
- Does not change `desk`'s or `mark`'s own output — `desk.summarize()` is reused,
  not duplicated.
