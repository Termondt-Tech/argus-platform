## Name

**Pherkad**, γ Ursae Minoris. **Chosen by Richard 2026-09-27.** The name is Arabic
*farqad*, "calf", short for *aḫfa al-farqadayn*, **"the dim one of the two calves"**. With
Kochab (spent on v0.4.7) it forms the **Guardians of the Pole**: two watchers that wheel
around Polaris and never set.

- **How it qualifies:** by tradition, on Kochab's and Arcturus's standing (a guardian is
  a watcher by definition). It is not literally an eye. **Found outside the pool, which is
  empty.**
- **The fit is the release's shape.** There are two guardians, and v0.5.2 switched one off
  (the credit trigger). The page that says whether anything is watching kept counting the
  switched-off one as on watch. This release teaches it which guardians are actually on
  duty. Pherkad is the dimmer of the pair, the one easy to forget is there, or to assume
  is there when it is not.
- **Sources for the etymology:** [Wikipedia, Pherkad](https://en.wikipedia.org/wiki/Pherkad);
  Ian Ridpath, [Star Tales: Ursa Minor](http://www.ianridpath.com/startales/ursaminor.html).

**Alternative offered and not taken: Thuban** (α Draconis), Arabic *thuʿbān*, "the large snake". It was the pole
star around 3942–1793 BCE, and Draco is Ladon, the dragon that never slept guarding the
Hesperides, so it qualifies by constellation and tradition. It fits "a guardian that must
not be counted awake when it is not", but less exactly than Pherkad's pair.
[Wikipedia, Thuban](https://en.wikipedia.org/wiki/Thuban);
[Wikipedia, Draco](https://en.wikipedia.org/wiki/Draco_(constellation)).

## What changed

### 1. `blind` means "no stop that can fire is evaluable" (review finding 1, blocking)

**Before.** `blind` was `unknown ⊇ {credit trigger, underlying trigger, profit target}`.
Under v0.5.2's strike-touch stop (`credit_trigger_enabled = false`), losing the SPX quote
while the legs still priced left:
- the underlying trigger unknown;
- the credit trigger and profit target "evaluable", though neither can close a losing
  position.

So the position read *degraded*: one Tier 2 row, a journal line saying *"backstop still
live"* (false), no page, and amber on `/status`.

**Now.** `blind` is measured against `TriggerThresholds.acting_stops`: the underlying
backstop, plus the credit trigger only while it is on.
- **With the credit trigger off, a dead SPX feed alone is blind.** It writes Tier 1
  `watchdog.unevaluable`, pages `watchdog_position_unevaluable`, and shows BLIND in red on
  `/status`.
- **With the credit trigger on, the test is the old one exactly**, because the profit
  target is unknown exactly when the credit trigger is. Every pre-existing `blind` test
  passes unchanged.
- The degraded journal line now names what is still live instead of asserting it.

`blind` decides nothing but the page and `/status`. No order, trigger or flatten changes.

### 2. An unreadable side is its own count, and the rule assumes the worst (finding 2)

**Before.** A leg, working order or ledger idea whose side could not be read counted
against **both** sides. For a rule on `|puts − calls|` that is exactly neutral: +1 to each
side changes no verdict. So an unknown idea that was really a put let a second put open.
The tests pinned the counts, never the refusal.

**Now.** Unknowns are counted under `unknown` (`RiskSnapshot.unknown_side_spread_count`).
The count is an upper bound on how far they can move the imbalance: `ceil(unknown legs / 2)`
plus every unknown ledger and working idea. An entry is admissible only if
`|known imbalance after| + unknown ≤ max_side_imbalance`, which is the exact worst case
over every assignment of the unknowns.
- The selector and the gate apply the same function to the same snapshot.
- **The rule is exact, not blunt**: with a put held and one unknown, a call is still
  admissible, because the book is 2–1 or 1–2 either way.
- **Reachable only on an unparseable OCC symbol, identifier or candidate key.** A dedicated
  SPXW book has none. So on a clean day this changes nothing, and `unknown` reads 0 on
  every record.

### 3. The per-side counts are pinned to trade ideas (finding 3c)

An AST test now holds what the design promised: `PositionWatchdog.open_spreads_by_side` and
`open_working_spreads_by_side` read `external_identifier` through `side_of_identifier`, and
never a symbol, a leg or an `occ_*` parser. Spreads chain, and a symbol-keyed count
undercounts exactly the chained same-side pair the side rule exists to stop (the fourth
standing landmine).

### 4. No page shows `credit_stop` as "the stop" while the credit trigger is off (Q4, Richard)

- **Pages.** `watchdog.page_view`, applied once in `PositionWatchdog._notify` (the sink
  every watchdog page and its journal line pass through), drops every `credit_stop` key at
  any depth and adds `"credit_trigger": "off"`. `_check_broker_agreement` pages directly and
  is pinned never to carry the key (it pages leg counts); so is `ExitExecutor`.
- **The spent-exit journal line** reads `cost_to_close=1.75, credit trigger off` instead of
  `… vs stop 1.70`.
- **`/status`**: the spent-exit row reads `mark: 1.75 (credit trigger off) — STILL THROUGH
  THE STOP`. The JSON carries `credit_stop: null` beside a new required
  `credit_trigger_enabled`.
- **The audit records keep `credit_stop`**, as the strike-touch decision says it stays
  recorded. The page is still built from the record's dict, so the one-builder rule holds;
  it drops one inert number rather than stating a different fact.
- **With the credit trigger on, every surface is unchanged.**
- Also fixed: `/status` prose that was false under the shipped config. The deferral cell
  now reads "its stop stays live to the close", not "stops live".

### 5. The side-balance design is amended to what was built (Q2, Richard: option b)

Docs only, no code.
- The single symmetric `max_side_imbalance` is accepted. **A put lean is a decision record
  plus a code + config release, never a config flip.**
- No `would_lean` field. Its counterfactual is a query over `refused` `signal.candidate`
  rows (design §8.4).
- **`_choose`'s `refused` label is now load-bearing for that query.** Change its meaning
  and the query must change in the same commit.

## Rules to carry

- **`blind` is measured against the stops that can FIRE (`acting_stops`), never the whole
  market set.** A switched-off trigger is not a watcher.
- **For a rule on a difference, "count it on both sides" is not fail-closed.** Carry the
  unknown separately and hold the worst case.
- **`admissible`, `rank` and `TriggerEvaluation.acting_stops` take their bound as a
  REQUIRED keyword.** A default is the silent way to reintroduce either defect.
- **Every watchdog page goes through `_notify`**, or is named in the AST sweep and pinned
  never to carry `credit_stop`.
- **A page drops an inert number; a record keeps it.** Never change what a record says to
  change what a page shows.
- **`_choose`'s `refused` label is load-bearing** for the side-balance counterfactual
  (design §8.4).

## Why it's safe

- **Every change only pages more or refuses more.** No new send path, no new exit
  behaviour, no config key, no size rail touched.
- **With the credit trigger on, #1 and #4 are exactly v0.5.2** (pinned both ways), so the
  documented rollback of the strike-touch stop (`credit_trigger_enabled = true`) restores
  the old pages as well as the old stop.
- **#2 changes a verdict only where a side is unreadable**, which a dedicated SPXW book
  does not produce. When it does, the change is a refusal, the safe direction for a rule
  that only ever refuses entries.
- **Each fix was mutation-tested:**

  | Change | Mutations | Caught |
  |---|---|---|
  | Findings 1–3 | 14 | 14 |
  | Q4 | 9 | 9 |
  | The flat-leg skip the review found untested (M11) | 1 | 1 |

  Every mutation was caught by the test written for it. Tables are in the review.

## What this release does NOT do

- **It does not change the strike-touch stop**, the caps, the side rule's band, the
  profit target (still off), or the flatten deferral's arithmetic or calibration.
- **It does not change what any audit record means.** `credit_stop` is still recorded;
  the new fields are additive.
- **It does not build a put lean**, an asymmetric band or a `would_lean` field (decided,
  Q2).
- **It does not add the `/status` Book row** owed since v0.5.2.
- **It does not fix the three review nits it left for a separate task.** Two are untested
  page details: `_register_cross`'s `is_working` guard (M5) and `working_close_for`'s
  preference for the resting cross (M12). The third is a pre-existing flaky rate-limit
  timing test.
- **It does not discharge any of v0.5.2's first-occurrence reads**; they are still owed
  (below).
