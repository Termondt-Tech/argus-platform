# v0.3.4 — Ain

*ε Tauri — the Bull's other eye, and the one star name that literally just means
"the eye". This release adds a second way of seeing rather than repairing one.*

A new read-only tool and the measurements that close two open questions. Requires
an image rebuild — `argus.tools.desk` is `src/`. **No config schema change**:
`argus.toml` changes here are comment-only, so an old config runs the new image
and vice versa.

## Added

**`argus.tools.desk` — the desk view.** The existing tools answer technical and
research questions; none of them answered "what am I holding, what did it make,
and what did it cost to get done". This one does:

- **open / held** positions, marked at the watchdog's own last look
- **closed intraday** with realized P&L computed from **actual fill prices**
- **fees** on filled orders, netted across opens and closes
- **execution quality** — reprices needed per entry, the closest thing this
  system has to an "adjustment" (it never rolls or legs into a position)
- **gate denials** grouped by reason

Read-only: `mode=ro`, no lock, safe mid-session alongside the supervisor, which
holds the writer lock for its whole life. `--date` defaults to today.

```
python -m argus.tools.desk --config /etc/argus/argus.toml
```

**It reuses `shadow.marker.read_executions` rather than scoring a second way.**
That is the same fill-based reconstruction `tools.mark` uses — attribution by
`external_identifier`, never a join to the mutable `orders` table — and a test
asserts the two produce identical `Execution` objects for the same trade, so they
cannot drift into disagreeing about the same fill.

**It deliberately does not do settlement.** A 0DTE position held to expiry produces
no fill event, so its terminal value is unknowable from the ledger and needs the
settlement print as an input. Held positions show their last intraday mark,
labelled as such, and the report points at `tools.mark`. Extrapolating that mark
into a number that looked like a result was the tempting wrong move.

One subtlety worth knowing: `watchdog.check` carries an `entry_credit` too, but it
is the ORDER LIMIT, documented as at-worst-slightly-low. The tool takes
`cost_to_close` from the mark and the credit from the fills; mixing them would
quietly bias every unrealized figure by the difference.

## Measured

**The Tier 1 evaluability flap is gone — 0.0% of ticks blind, against 27.8%
pre-fix.** Measured on 2026-08-18 across 43,104 watched ticks: 0 Tier 1
`watchdog.unevaluable` records, against 1,517 on 2026-08-13, and 0 distinct blind
episodes. Fix C eliminated it rather than reducing it; the 2,954 Tier 2
`watchdog.degraded` records are the re-levelling working as designed.

**No settle allowance is owed**, and the `[watchdog]` key sketched in the original
finding is deliberately not added — there is no condition left for it to suppress.
This closes the last of the live-fire pass's findings except the inert daily
max-loss breaker, which remains a LIVE-FLIP GATE and is unfixable in sandbox.

→ [live-fire pass, Finding 5](../decisions/2026-08-13-live-fire-sandbox-pass.md)

**The audit write rate is 2.33/s, of which only 0.20/s is Tier 1.** `argus.toml`'s
`[audit] synchronous` comment cited a stale ~1.7/s basis and still described the
post-Fix-C measurement as owed. Both corrected. The total ROSE while the cost
FELL, because the flap moved from Tier 1 to Tier 2 — the pre-fix prediction was
right about the tier that pays the fsync and wrong about the aggregate. At 0.20
Tier 1 records/sec, `FULL` costs roughly 16 microseconds per second of runtime.
