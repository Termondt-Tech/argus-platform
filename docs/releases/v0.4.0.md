## Name

**`Aldebaran`** — α Tauri, "the Eye of the Bull": the steady, bright one, the
classic eye, and the pool's longest-held reservation. Its waiting reading was
*"a clean, steady re-watch rather than a fix for something that flickered — the
live-min-size flip, or the first genuinely uneventful week."* Spent here on the
go-live-enablement release rather than held for the flip: **Richard's call,
2026-09-10.** The fit is the "clean, steady" half — v0.4.0 makes the traded
account something the loader refuses to start without naming, and makes the
watchdog something one exception can no longer switch off. Preparation for a
steady watch, not a repair of a broken one. Qualifies literally on etymology, no
tradition allowance needed.

**`Rastaban` stays reserved** — dual-watchdog / consensus, a different shape;
this release narrows an existing halt rather than adding a second verification
loop. **The pool is now Rastaban alone** — every release after this one takes a
found name until the pool is refilled.

### 1. Pinning the traded account

→ design: [2026-09-10-pinning-the-traded-account.md](../designs/2026-09-10-pinning-the-traded-account.md)
→ decision: [../decisions/2026-09-10-pinning-the-traded-account.md](../decisions/2026-09-10-pinning-the-traded-account.md)

The enforcement half (option **D**) of
[the live account is not dedicated](../decisions/2026-08-31-live-account-is-not-dedicated.md),
closing **C9** in [`docs/go-live-findings.md`](../go-live-findings.md). Four rails
read a WHOLE-ACCOUNT number and treat it as an Argus-only number — reconciliation's
position map, the concurrency cap's leg count, the daily-loss breaker's NLV
anchor, the relative size rail — so the live account must be dedicated to Argus,
and a dedicated account that is merely *assumed* is one re-ordered
`GET /customers/me/accounts` away from not being the one. Today the process takes
`accounts[0]`.

- **`[broker] account_number`** — `str | None`, optional in the loader, present
  in all three profiles. `argus.live.toml` pins `"5XX00000"` (the existing
  account being made dedicated under **C8**, not a new one); `argus.sandbox.toml`
  and `argus.dev.toml` ship `""`, normalized to `None` = unpinned = `accounts[0]`,
  byte-identical to today's behaviour. **Cert stays unpinned by decision,
  permanently** — cert accounts are re-provisioned by tastytrade and a pinned
  number that stops existing is a permanent `SessionAborted` that parks the
  process.
- **The live guard is its own branch** in `Config.from_dict`, placed with the
  `[broker]` parse and therefore firing **before** the `account_stream_max_age_s`
  and `audit.synchronous` live guards — the three refuse live for three unrelated
  reasons and `test_config.py::test_the_three_live_guards_are_independent` stops a
  tidy from folding them.
- **`__main__` passes `config.broker.account_number` explicitly**; `Application`
  does not re-derive it (the injection seam is what `tools/shadow.py` uses).
  `tools/shadow.py` falls back to the config; `tools/account.py`,
  `tools/loop_lag.py`, `tools/order_smoke.py` untouched.
- **`/status`** gains an **Account** row after Credentials, and the JSON's
  top-level `"account"` block carries `pinned` (bool) and `number`. The unpinned
  row renders **muted and explains itself** (D7) — never amber, because unpinned
  is the intended permanent cert state and unreachable in live.
- **The reconcile diagnostic** — a live-only, positions-only sentence on the
  `reconciliation_mismatch` alert naming a shared account as the likely cause,
  fired only when *every* position discrepancy is `unexpected_at_broker`.
  **Diagnostic only: changes no verdict, grade, or halt** —
  `test_the_hint_changes_no_verdict` is the bound.
- **No rail changes behaviour.** Cert is a no-op by construction. Option B (a
  strategy-scoped accounting layer) was evaluated and rejected in the 2026-08-31
  record; nothing here is a step toward it.
- Build corrections, in the decision record: the new top-level `"account"` JSON
  block would have clobbered an existing one; and a live `Config` built through a
  test helper the design's §4.5 breakage list could not see.
- **`MAX_SANDBOX_LIVE_DIVERGENCE` now sits at exactly the cap of 10** (D8) — the
  prompt to reopen the base+overlay question, not to raise the number. This also
  greened `test_value_divergence_is_declared`, which had been failing on `main`
  since the live-min-size risk numbers landed without an allowlist entry (noted
  in v0.3.22's scope as pre-existing).

**Still not closed here:** the account must *stay* dedicated (operator
discipline, not a rail); cash movements contaminate the breaker; the NLV floor
(~$31,667 at `position_size_pct = 0.03`); and the breaker is still unexercised.
All on the live-flip checklist. **C8** — the account actually being empty of
everything Argus did not place — is a separate gate confirmed by a clean
`reconcile.clean` at the cutover.

### 2. A rung that never worked is not a verdict either

→ design: [2026-09-10-never-worked-identifier-wide.md](../designs/2026-09-10-never-worked-identifier-wide.md)
→ decision: [../decisions/2026-09-10-never-worked-is-not-a-verdict.md](../decisions/2026-09-10-never-worked-is-not-a-verdict.md)
→ sibling: [a terminal rung is not a verdict](../decisions/2026-09-02-a-terminal-rung-is-not-a-verdict.md)

The **third instance** of one class (2026-08-26 twice, 2026-09-02 once): a walk
concluded "no fill" from a fact about one **rung** without asking the
**identifier**. On 2026-09-09 `call-7660-7670` reported
`never_worked / filled_contracts 0 / steps 1` while the ledger held 1 contract at
0.55 (rung 0's limit — `_reprice` had moved `state.sent`, so the reported 0.50
was the replacement's). `_await_in_market`'s deadline branches concluded off a
**clock** with the broker having said nothing. Position safety was never at risk
— `positions` is written from the fill feed independently of the walk, so the
spread was still adopted, watched and exited for +40.00 — but the walk's own
record was wrong, and on the exit path that spends the position's one attempt.

- The identifier-wide FILLED probe moves from `_resolve` into **`_finish`** — the
  sole constructor of every `WalkResult` in the module, the only place the rule
  is an **invariant** rather than a habit — gated on a frozen
  `_ASK_BEFORE_CONCLUDING` outcome set. `_NEVER_ASKS` is its disjoint complement;
  `test_every_outcome_is_classified` fails on both union and disjointness so a
  new `WalkOutcome` cannot join unclassified.
- `_resolve`'s own probe call is **deleted** (two sites double-asked every
  `REJECTED`). Three `probe=False` sites where `by_identifier` was just read;
  default `True` and it must stay so.
- **`ABORTED` excluded as a safety rail** — a halt must not add a broker round
  trip.
- **Build overturned one claim:** on the exit path the gate does not merely
  duplicate `_await_settled`'s read — it **pre-empts** it, so a cancel/fill cross
  now reports `FILLED` rather than `FILLED_LATE` (Tier 2:
  `suppressed_outcome: walked_away`; nothing load-bearing moved,
  `test_a_fill_that_crosses_the_cancel_is_reported_and_not_crossed` updated).
- **`src/` only** (`loop.py` plus one additive comment beside `watchdog.py`'s
  `_RETRYABLE_EXITS`). No config key, no migration, no new audit category.
- Rule to carry: **the trigger for asking is that the WALK is about to conclude,
  not that the BROKER already did**, and **`_finish` is the only place the rule
  can be an invariant rather than a habit.**

### 3. A watchdog exception must not take the watchdog

→ design: [2026-09-10-a-watchdog-exception-must-not-take-the-watchdog.md](../designs/2026-09-10-a-watchdog-exception-must-not-take-the-watchdog.md)
→ decision: [../decisions/2026-09-10-a-watchdog-exception-must-not-take-the-watchdog.md](../decisions/2026-09-10-a-watchdog-exception-must-not-take-the-watchdog.md)

The last open halt-scope question ([go-live findings §3](../go-live-findings.md)).
`_halt_on_exception` took the watchdog down **three independent ways** and the
finding named two: `self._stop.set()` (the **shared** session stop event, which
also aborts an exit walk in flight), `_halt(...)` with no `grade=` → `ALL` →
`request_stop()` (the process parks), and **`return` from `run()`** (the watchdog
task itself — *the one that has to be fixed for either of the others to help, and
it was in no write-up of this finding*). Fixing only the first two yields a
session that runs to the close with `/status` reporting `running` and nothing
watching a held 0DTE position — **strictly worse than the old behaviour**, where
the hard stop at least prompted the restart that recovered the 2026-09-03
position in eight seconds.

**Measured cost: ≈ $670 on 2026-09-03**, and the day supplied its own control —
two adjacent call spreads triggering `credit_multiple` five minutes apart:
`call-7720-7725`'s watchdog survived and it exited at −190.00; `call-7725-7730`'s
was taken down by the halt and it closed after the manual 15:37 restart at the
full 5.00 width (−860.00, identical to settlement), while priced at 1.65 the
second it was abandoned.

- **A watchdog exception now engages the kill switch at `HaltGrade.ENTRIES` and
  KEEPS WATCHING.** Entries stop immediately and permanently (a watchdog that
  raised cannot be trusted to stop out what a new entry would open); everything
  else runs on (the watchdog is the only thing that can close or flatten what is
  held). The grade is the verdict's own property, passed by the watchdog — P3's
  rule.
- **Per-position isolation** — the catch is around each spread's evaluation, so
  one poisonous spread cannot blind its sibling (the 2026-09-03 harm reproduced
  by a different route on a two-position book).
- **Two hazards that only exist once the watchdog survives**, both closed here: a
  crashed exit task must **spend the position's attempt** (as `NOT_RESOLVED` with
  a new `crash_error` sentence — a *fourth sentence, not a fourth outcome*), or
  the next tick double-closes; and **`_reap_exits` must run in a `finally`**, or
  an aborted pass drops that position from the watch list for the process
  lifetime.
- **`AuditWriteError` is the one load-bearing exclusion** — it has already halted
  `ALL` through `on_failure` before it reaches this module, so it keeps today's
  path verbatim and `run()` returns.
- **`/status` gains a Watchdog row** (WATCHING / DEGRADED / RECOVERED) — a
  degraded watchdog that keeps running is by construction the quietest failure
  this system can produce, so the row is not optional. The RECOVERED (amber)
  state exists because the halt is permanent and the failure is not: entries stay
  halted until `POST /resume?confirm=yes`.
- `self._fatal` / `fatal` renamed to `_failure` / `last_failure`.
- **`src/` only** (`execution/watchdog.py`, `execution/escalation.py`,
  `status.py`, `session.py`). No config key (`_DEGRADED_PAGE_INTERVAL_S` is a
  module constant), no migration. Three new `watchdog.*` audit categories
  (`watchdog.degraded` T1, `watchdog.degraded_still` T2, `watchdog.recovered` T1,
  `watchdog.exit_crashed` T1); four alert kinds.
- **Operating-note change** — see `README.md` / the runbook: **deciding whether
  to restart is now the operator's call.** A transient is already recovered and a
  restart buys nothing; a defect that repeats every tick repeats after the
  restart too. The one thing a restart buys is a *clean* watchdog state, which
  matters if a position's exit attempt was spent by a crash.
- **Not closed:** the confirmation-gated exit re-attempt stays an open decision;
  this is not a step toward it.
