# v0.3.8 — Ain al-Rami

*ν Sagittarii, "the Eye of the Archer" — the archer's eye is what aims: it says
which target a shot is for, never what the shot is worth once loosed. This
release found the entry gate asking that same eye of a leg that was never aiming
at anything.*

> Spent from the pool reserved for it — the first time that has happened. Alterf
> (v0.3.6) and Polaris (v0.3.7) were both found outside the table because neither
> reserved candidate matched those releases' shape. Ain al-Rami's own stated
> reading — "aim or targeting — strike selection, the delta target" — lands on
> this release almost literally: it is exactly the distinction between the leg
> chosen BY delta (the short strike, the aim) and the leg chosen by strike
> distance (the long leg, not aimed by anything). Aldebaran remains reserved,
> still waiting for a clean steady re-watch or the live-min-size flip. See
> [releases/README.md](README.md#release-names--arguss-eyes).

Requires an image rebuild — `src/argus/signal/live_chain.py` and
`src/argus/signal/strategy.py` both change. **No config schema change**: this is
a role split inside the existing admission rule, not a new threshold.
`staleness.market_data_max_age_s` and every other key in `argus.toml` are
untouched, unlike the last three releases. An old config runs the new image and
vice versa.

## Fixed

**The entry gate demanded fresh greeks of both legs of a vertical, and only one
of them is ever chosen by a greek.** Closes A1's own recorded open question — the
admission rate its 2026-08-21 freshness gate produces over a full RTH session —
which could not be answered until `[marketdata] source = "live"` had run one.

The first live-quote session (2026-08-24) answered it at **~4.3%**: `signal.skip`
fired on 4,357 of 4,552 loop iterations, a counter that had never fired before in
the database's history. The cause was entirely the greeks feed, never the quote
feed — across 1,520 session heartbeats, every greek in the 120-symbol chain was
stale on 95% of samples, while every quote was stale on zero samples, ever,
all-time. `admissible` (A1's gate) was a pure function of the greeks feed's lag.

The short strike is chosen BY delta magnitude (`target_short_delta`); the long
leg is chosen by strike distance and priced off its own market, contributing no
delta to selection, credit, width, or max loss — delta is the only greek Argus
reads anywhere. A1's gate held both legs to the same bound on both fields, so the
long leg's requirement — which protected nothing — was what starved the day.

It also deformed the trades that DID get through. With the long leg's nearby
strike gated out, the long-leg search walked to the next VISIBLE strike:
2026-08-24 produced the first 10-wide spread and the first 1-contract position in
the record (`max_loss_per_position` clamping what a 5-point ladder would have
sized at 2), plus `position_max_loss_exceeded` / `size_cap_exceeded` gate denials
seen on no prior day. The sizing rails were correct throughout — the ladder handed
to them was already deformed by the gate above.

**Fixed by scoping admission to the leg's role, not by loosening the bound.** A
fresh quote admits a leg into the chain snapshot; fresh greeks decide only
whether it may be selected as the SHORT strike. `OptionQuote.delta` is now
`float | None` — `None`, deliberately never NaN: `SpreadSignal.underlying_price`
uses NaN because its one consumer is a comparison, where NaN fails CLOSED. This
field's one consumer is `min()`, where NaN fails OPEN — a NaN key never loses a
comparison, so `min` would have returned it. Short-strike selection now runs over
`legs` filtered to `has_delta`, refusing a stale or missing delta exactly as
before; what changed is WHERE that refusal happens — at strike selection, the
first point a leg has a role, rather than at admission, before it has one.

`ChainCoverage` gained `short_admissible` (`<= admissible`, off the same `_admit`
call both `snapshot()` and `coverage()` share, so the two counts can never drift
from each other): a full ladder with `short_admissible == 0` is now visible as the
lagging-greeks state it is, rather than reading identical to an empty chain.
`_select` reports a dedicated `no_short_leg_with_fresh_delta` reason for the same
case, ranked above an empty ladder so the more informative diagnosis wins the
headline.

Verified against a regression test built to the 2026-08-24 shape (a long-leg
strike with a fresh quote and lagging greeks, previously invisible, forcing the
search out to the next strike) rather than by a live re-run — built and tested off
the droplet, against `argus.dev.toml` only; `argus.db` was never touched.

**What this does not do: it does not make the greeks feed faster.** On a day
shaped like 2026-08-24, a short strike is selectable about as often as before.
What changes is that the spread built around it is the correct one, the
starvation is named (`no_short_leg_with_fresh_delta`) rather than silent
(`signal.skip`), and `short_admissible` is now the number to watch if this needs
to go further — the DXLink greeks subscription itself, not this gate.
→ [role-scoped admission](../decisions/2026-08-24-entry-leg-admission-is-role-scoped.md)

## Deploy

Rebuild only — no config to move with it.

```bash
cd /opt/argus
scripts/argus-deploy.sh --dry-run v0.3.8   # show the plan, touch nothing
scripts/argus-deploy.sh v0.3.8             # deploy it
```

Equivalent manually, per the runbook (§17): `git fetch --tags && git checkout
v0.3.8` (NO sudo on either), verify with `git describe --tags` and
`git status --short`, then `sudo docker compose build && sudo docker tag
argus:local argus:v0.3.8 && sudo systemctl restart argus.service`.

**Rollback needs only one half this time.** Because `argus.toml` is unchanged,
either `git checkout v0.3.7` alone or `ARGUS_IMAGE_TAG=<v0.3.7 image>` alone is a
complete rollback — the two-halves-not-independently-safe warning the last three
releases each carried does not apply here. No dependency change either;
`requirements.txt` is untouched and the `--require-hashes` build is unaffected.

**This release touches live paths directly.** `argus.toml` carries
`environment = "sandbox"` with `dry_run_submissions = false` (live fire against
cert), and the entry path this release changes is the one that builds every order
Argus submits. Confirm the deployed config still matches before restarting, same
as every release before it.

## Scope

**Answers and closes A1's recorded open question.** `docs/decisions/README.md`'s
open-questions table drops from seven rows to six.

**Does not by itself justify scaling entry size.** CLAUDE.md's live-min-size flip
is gated on the admission rate being measured before size moves — it now has
been, but the number that measurement produced (~4.3%) was a bug's output, not
the strategy's behavior under a healthy greeks feed. The number that should
inform a scaling decision is whatever the NEXT RTH session measures post-fix, not
the one this release explains. **Hold size where it is until a clean post-fix
session confirms the fix.**

**One item from the same investigation was re-checked, not separately fixed.**
Candidates built at >=15-point widths (needing >=2 consecutive missing strikes on
a 5-point ladder) traced to the same ladder-hole mechanism and are resolved by
this fix's own regression test directly. No separate guard was added, and none is
owed unless a live session shows otherwise.

**The daily max-loss breaker remains structurally inert in sandbox**, unchanged
by this release — day P&L is derived from NLV and cert never marks NLV. Proving
that rail out is still a live-flip gate this release does not close.
