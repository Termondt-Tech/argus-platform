# v0.3.6 — Alterf

*λ Leonis — "the Glance," the Lion's momentary look, from Arabic aţ-ţarf. This
release found a page that looked once at an open position it could not close and
never looked again. Alterf became a held gaze: the same check, repeating for as
long as the position stays unclosed.*

> New to the pool this release — a real star that earns "the eye" by tradition
> rather than literal etymology, same standing as Alcor's. See
> [releases/README.md](README.md#release-names--arguss-eyes).

**Requires an image rebuild AND a config change, and they must deploy together.**
This is a `src/` release, and it adds a REQUIRED key —
`[watchdog] exit_unattempted_max_s`. The v0.3.6 image against a pre-v0.3.6
`argus.toml` refuses to start with
`missing required config key: watchdog.exit_unattempted_max_s`. See **Deploy**
below.

Found by the first intraday stop since v0.3.5 — the first day this run exercised
the exit path at all, rather than entries only.

## Fixed

**Exit-order construction was gated by an entry-only invariant, and the 1.0–2.0s
band it created was a dead zone.** `execution.signal_max_age_s` (1.0) exists so an
entry's submitted price cannot drift from the price the pre-trade gate approved —
it bounds the handful of milliseconds between gate-pass and construction. No such
invariant exists on the exit path; nothing gates an exit. But
`ExitExecutor._build_exit_order` passed that same value into the shared builder,
while the watchdog fires triggers against `staleness.market_data_max_age_s` (2.0).
A 0DTE wing sits in that 1.0–2.0s band routinely, so triggers fired there could
never become orders. The day's own stop hit it at **1.313s**:

```
signal is 1.313s old, past the 1s construction tolerance;
refusing to build an order from a price the gate did not see
```

**Fixed** — exit construction now keys off `market_data_max_age_s`, the bound the
watchdog's own quotes are already held to. A bound is kept, not removed: past the
trigger's own threshold there is nothing honest to price from. `signal_max_age_s`
is untouched and stays entry-only.

**The retry was unbounded and correctly so, but the SILENCE was not.** A triggered
position with no order in the market retries every cadence tick forever —
abandoning would strand an open 0DTE position, and burning the one exit attempt on
an order that was never sent would be worse. But before this release, both no-order
paths (`watchdog.exit_unattempted`, `watchdog.exit_unpriceable`) escalated on the
rising edge and then went quiet forever while the retry kept spinning.

**Fixed** — `watchdog.exit_still_unplaced` fires every `exit_unattempted_max_s`
(30.0s) for as long as the condition holds, on both no-order paths, naming which one
and how long. **It repeats rather than firing once**, deliberately: a single page is
one missed notification away from restoring the exact silence this exists to
prevent, and for "an open 0DTE position cannot be closed" that is the wrong side to
err on. The rate stays bounded twice over without suppressing the repeat — per
INTERVAL here (~1 Tier 1 write per 30s), and per KIND at 900s inside
`SlackNotifier`, which folds the rest into a `(+N suppressed)` count. Deliberately
NOT a halt: halting would stop the retries that are the only thing still trying to
close the position.
→ [exit freshness](../decisions/2026-08-20-exit-order-freshness-bound.md)

**`held_but_unbooked` paged on ordinary post-exit propagation lag, one entries-only
day after the entry-side version of the same lag got an allowance.**
`book_settle_s` (v0.3.0) was calibrated on a day with entries only and wired to one
direction: on the way in, Argus's ledger books an AlertStreamer fill before the
broker's own book reflects it. The exit side is the mirror — the ledger deletes the
position row the instant its own closing fill books, and the broker's book trails
it. Measured: paged **1.215s** after the closing fill, cleared **6.012s** later on
its own.

A blanket timer in this direction is the wrong fix — `held_but_unbooked` means a
position may be held with no virtual stop being evaluated, and suppressing that on a
clock alone would delay the one page this check exists to send.

**Fixed** with an EVIDENCE gate instead of a timer. `PositionWatchdog.note_fills`
records the OCC symbol of every leg one of Argus's own **closing** fills took to
**flat**; a `held_but_unbooked` disagreement is suppressed only when that record
covers the excess legs. **A disagreement with no matching closing fill still pages
immediately and unconditionally** — no fill, an opening fill, a partial close, or an
excess larger than what was actually closed all still page on the first
observation, exactly as before. The evidence's own lifetime is the window
(`book_settle_s`, the same knob — same lag, same reason not to add a second one
meaning the same thing).
→ [held-but-unbooked after our own exit](../decisions/2026-08-20-held-but-unbooked-after-our-own-exit.md)

**A previous kill-switch trip could show as a live one after a restart.**
`kill_switch.source`/`since` in `/status`'s JSON came from the newest
`kill_switch.trip` audit row, which outlives the process that wrote it — the switch
itself is process state with no reset. So after a restart, a past trip's source and
timestamp appeared next to `engaged: false`, reading as a halt that was not
happening. The HTML view already guarded on `engaged`; the JSON did not.

**Fixed** — gated on `ks.engaged`, matching how `halted` already derives its source
and since from the live halt object. The trip itself is unchanged in the audit
tail, where history belongs.

## Documentation

**`OpenSpread.entry_credit`'s bias is 9-18% (n=2), not "slightly."** The docstring
called the gap between the filled opening order's limit and the realized fill
"at worst slightly LOW" — a rounding-error framing. Two measurements now put it at
9.1% (2026-08-19, previously dismissed as "not a defect" on the strength of that
word) and 18% (2026-08-20). Still the safe direction: the low basis means
`credit_stop = credit_multiple × entry_credit` fires slightly early, not late. But
**no conclusion about `credit_multiple` may be drawn from a dataset measured
against this basis** — some or all of any "2x stops out too often" observation is
this bias, not the multiple. Correcting it needs `FillInfo.fill_price` captured
durably (a new column and migration): DEFERRED, see below. Comment-only change, no
behavior affected.

**`CLAUDE.md` re-audited against its own ~300-line rule.** Flagged at 306 lines on
2026-08-12, drifted to 400 across the fixes above. 400 → 373: settled-investigation
narrative that already lives in `docs/decisions/` was trimmed to one current-state
sentence plus a pointer, per the file's own convention. Every trimmed fact was
verified present elsewhere before being cut; none was orphaned. Also fixed a
pre-existing miscount ("Three standing landmines" over four bullets).

## Deferred

**Capturing `FillInfo.fill_price` for a precise `entry_credit` basis** — the item
that would fix the 9-18% bias above at its source. Explicitly not pulled forward
here: it is a new column plus an immutable migration, a different risk class from
an alerting/order-construction release, and the two measurements behind it are both
**sandbox** numbers — cert proves API contracts and wiring, never realistic fill
behavior, so sizing a migration off it is the same guess the rest of this codebase
is built to avoid. Land it after live-min-size produces real limit-vs-realized
fills; that data point is also what tells you whether the migration is worth it at
all.

## Deploy

Rebuild plus config, moving together. The tag carries both.

```bash
cd /opt/argus
git fetch --tags
git checkout v0.3.6
git describe --tags && git status --short
sudo docker compose build
sudo docker tag argus:local argus:v0.3.6    # or the rollback below has no target
sudo systemctl restart argus.service
```

**The two halves are not independently safe:**

- **New image + old config → hard refusal at startup**, `ConfigError`. Fail-closed
  and loud, which is the good failure.
- **Old image + new config → runs, silently unfixed.** The pre-v0.3.6 loader
  ignores the unknown key rather than rejecting it, so nothing announces that the
  exit-silence bound is not active. Rolling back the image alone leaves exactly
  this.

A full rollback needs both halves as usual — `git checkout v0.3.5` for code and
config, `ARGUS_IMAGE_TAG=<v0.3.5 image>` in `.env` for the image.

**No dependency change** — `requirements.txt` is untouched and the
`--require-hashes` build is unaffected.

**This release touches live paths directly.** `argus.toml` carries
`environment = "sandbox"` with `dry_run_submissions = false` (live fire against
cert), and both exit-construction and reconciliation-alerting fixes are on that
path. Confirm the deployed config still matches before restarting.

## Scope

Not sandbox-specific; both mechanisms are identical in live. **Not a live-flip
gate** — the daily max-loss breaker remains structurally inert in sandbox, unchanged
by this release, and stays the one open item before size is scaled.

**Bound what this release proves.** Both exit-path fixes were exercised by ONE real
intraday stop, not by a range of conditions. What is still unverified: a second
trigger firing on the same position while an exit is already in flight, the
market-crossing escalation combined with the freshness-bound change, and the
`exit_still_unplaced` repeat under an actually-unclosable position (bounded and
tested against a fake clock; not yet observed against a real one).
