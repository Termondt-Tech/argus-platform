### Q4, built (2026-09-27)

Richard's answer to Q4: while `watchdog.credit_trigger_enabled` is false, no page shows
`credit_stop` as the stop. There is one rule, `watchdog.page_view`, applied at
`PositionWatchdog._notify`, the sink every watchdog page and its journal line pass
through. It drops every `credit_stop` key at any depth and adds `"credit_trigger": "off"`.
The rule also reaches:

- **the spent-exit journal line**, which reads `cost_to_close=…, credit trigger off`;
- **`/status`'s spent row**, which reads `mark: X (credit trigger off)`, with JSON
  `credit_stop: null` beside a new required `credit_trigger_enabled`, carried through the
  swept `_to_unclosable` seam.

**Records keep `credit_stop`**, since the decision record keeps it recorded. With the
credit trigger on, nothing changes.

`self._alert` directly. Its detail is leg counts, so it is named in the test as the one
direct pager and pinned never to carry the key; `ExitExecutor` is pinned the same way.
